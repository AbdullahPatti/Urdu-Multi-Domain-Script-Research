PART 0 — CONTEXT AND RULES
────────────────────────────────────────────────────────────────────────────────

The goal is to measure domain robustness of NLP models in Urdu. The setup is:
  - Language is FIXED (Urdu)
  - Script is FIXED per task group (Nastaliq or Roman)
  - NLP Task is FIXED per task group (e.g., hate speech, sentiment)
  - Only the DOMAIN varies (different sources, topics, styles)

We conduct both IN-DOMAIN and CROSS-DOMAIN experiments:
  - IN-DOMAIN:    train on Domain A, test on Domain A
  - CROSS-DOMAIN: train on Domain A, test on Domain B (and all other pairs)

We report averages across all pairs per task, matching the structure of
Tables 4 and 5 from the EMNLP paper.

DO NOT:
  - Change the language
  - Change the script
  - Mix Nastaliq and Roman tasks
  - Include multilingual or cross-lingual settings

PART 4 — DATA PREPARATION STEPS (DO THESE BEFORE ANY TRAINING)
================================================================================

STEP 4.1 — Verify all splits exist
  - Check that every domain folder has train.csv and test.csv.
  - Each CSV must have exactly two columns: "text" and "label".
  - No NaN values in text or label columns.
  - Verify row counts match expected totals.

STEP 4.2 — Label standardization per task (do at data loading time in code)

  Task 1 — Nastaliq Sentiment Analysis:
    Map all labels → 0=Negative, 1=Positive
    Drop all Neutral samples (to make binary, consistent with Domain B).
    Domain B: 0→0 (Negative), 1→1 (Positive)
    Others: "Negative"→0, "Positive"→1, "Neutral"→DROP

  Task 2 — Nastaliq Hate Speech:
    Map all → 0=Not-Hate, 1=Hate
    Domain A/B: already 0/1
    Domain C/D: "Hateful"→1, "Non-hateful"→0
    Domain E: already 0/1

  Task 3 — Nastaliq Fake News:
    Map all → 0=Fake, 1=Real
    Domain A: folder-based (Fake/→0, Real/→1)
    Domain B: "FAKE"→0, "TRUE"→1
    Domain C: Fake file→0, Real file→1
    Domain D: "Unreal"→0, "Real"→1

  Task 4 — Nastaliq QA:
    No label mapping needed (question/answer pairs).
    text = question, label = answer (string, not numeric).

  Task 5 — Roman Product Reviews:
    Map → 0=Negative, 1=Neutral, 2=Positive  (3-class)
    OR binary (drop Neutral): 0=Negative, 1=Positive.
    CHECK: all 5 domains for label consistency before deciding.
    RECOMMENDED: Use 3-class if all domains have Neutral; drop Neutral otherwise.

  Task 6 — Roman Sentiment Analysis:
    Domain B is binary (pos/neg). Drop Neutral from others.
    Map: pos/Positive→1, neg/Negative→0, Normal/Neutral→DROP

  Task 7 — Roman Cyber Abuse:
    Map all → 0=Not-Abusive, 1=Abusive
    Harmful→1, Non-harmful→0, Abusive→1, Non-abusive→0

  Task 8 — Roman Twitter Opinions:
    Domain A is binary (0/1). Verify: 0=Negative, 1=Positive.
    Drop Neutral from B/C/D to match binary format.

PART 6 — EXPERIMENT PROTOCOL (HOW TO RUN IN-DOMAIN AND CROSS-DOMAIN)
================================================================================

DEFINITIONS:
  N = number of domains in a task
  S = source domain (training domain)
  T = target domain (test domain)
  SS = train on S_train, test on S_test          ← in-domain score for S
  TT = train on T_train, test on T_test          ← in-domain score for T
  ST = train on S_train, test on T_test          ← cross-domain score

METRICS (from the paper):
  SD (Source Drop)   = SS − ST    (how much the model degrades when tested on T)
  TD (Target Drop)   = TT − ST    (how much T would have been better with its own data)
  WSD (Worst SD)     = max over all pairs (S,T) of SD
  WTD (Worst TD)     = max over all pairs (S,T) of TD
  Avg In-Domain      = mean of all SS scores (one per domain)
  Avg Cross-Domain   = mean of all ST scores (one per ordered pair)
  Avg SD             = mean of all SD values
  Avg TD             = mean of all TD values

NUMBER OF EXPERIMENTS PER TASK PER MODEL:
  N domains → N in-domain runs + N×(N-1) cross-domain runs = N² total runs
  N=4: 16 runs per model per task
  N=5: 25 runs per model per task

HOW TO ENUMERATE EXPERIMENTS:
  For a task with domains [D1, D2, D3, D4]:
    In-domain:    (D1,D1), (D2,D2), (D3,D3), (D4,D4)         = 4 runs
    Cross-domain: (D1,D2), (D1,D3), (D1,D4),                   = 12 runs
                  (D2,D1), (D2,D3), (D2,D4),
                  (D3,D1), (D3,D2), (D3,D4),
                  (D4,D1), (D4,D2), (D4,D3)
    Total: 16 runs

  For N=5 (Tasks 1, 2, 5): 25 runs per model per task

TOTAL RUN COUNT:
  Fine-tuned models (3): mBERT, XLM-R, BERT-Urdu
    Task 1 (N=5): 3 × 25 = 75
    Task 2 (N=5): 3 × 25 = 75
    Task 3 (N=4): 3 × 16 = 48
    Task 4 (N=4): 3 × 16 = 48
    Task 5 (N=5): 3 × 25 = 75
    Task 6 (N=4): 3 × 16 = 48
    Task 7 (N=4): 3 × 16 = 48
    Task 8 (N=4): 3 × 16 = 48
    TOTAL FINE-TUNED RUNS: 465

  Few-shot LLMs (3): llama3.1, gemma2, qwen2.5
    Only cross-domain runs needed (N×(N-1) per task)
    Also include in-domain (k-shot from same domain) for fair comparison
    Same count as above: 465 LLM runs
    But LLM runs are inference only (no training), so much faster per run.

  GRAND TOTAL: ~930 experiment runs across all models.

OUTPUT PER RUN:
  Save to: results/task_name/model_name/S_vs_T_results.json
  Contents: {
    "source": "Domain_A_...",

PART 8 — TABLE 4 AND TABLE 5 FORMAT (WHAT TO REPORT)
================================================================================

TABLE 4 FORMAT (replicate exactly from paper):

  Rows: Each NLP task (Hate Speech, Sentiment, Fake News, QA, etc.)
  Columns per model (mBERT, XLM-R, BERT-Urdu):
    SS      = Avg In-Domain F1 (averaged over all N domains)
    ST      = Avg Cross-Domain F1 (averaged over all N×(N-1) pairs)
    SD      = Avg Source Drop = SS − ST
    WSD     = Worst Source Drop (max SD across all pairs)
    TD      = Avg Target Drop = TT − ST (averaged)
    WTD     = Worst Target Drop

  Example cell values: 0.XX (macro-F1, 2 decimal places)

  Interpretation:
    High ST = model is domain-robust
    High SD = model "overfits" to source domain vocabulary/style
    High TD = training on target domain would have helped significantly
    Low WSD = no single pair causes catastrophic failure


TABLE 5 FORMAT:

  Rows: Each NLP task
  Columns: Fine-tuned (best model), LLM1 (llama3.1), LLM2 (gemma2), LLM3 (qwen2.5)
  Metric: Average Cross-Domain F1 (ST) for each
  Additional: Compare In-Domain fine-tuned vs Cross-Domain LLM
  Goal: Show whether LLMs generalize better across domains than fine-tuned models
